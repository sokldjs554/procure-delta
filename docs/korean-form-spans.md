# 한국어 공고 서식 해석 v3

기존 OCR 후보는 원본 스캔의 지정 문자열을 더 잘 읽었지만 필수 구조화 필드를
충족하지 못했다. 이번 변경은 인식 모델을 교체하지 않고, 이미 읽힌 명시적
서식만 `deterministic-labels-v3` / `explicit-labels-v3` 규칙으로 해석한다.
제목·발주기관·분류의 필수 조건, 전체 결과 거절, 출처 해시·페이지·정확한 인용,
문서 간 충돌 검증과 upstream 우선 규칙은 유지한다.

## 지원 범위

- 완성된 공고 표제의 괄호는 `()`, `[]`, `（）`, `［］`를 각각 짝으로 허용한다.
  서로 다른 괄호를 임의로 고치지 않는다. 기존 입찰공고·입찰설명서·소액수의
  설명서·조달물자 구매입찰공고 문법만 허용한다.
- 표제가 두 인접한 비어 있지 않은 줄에 걸쳐도 합쳐서 완전한 문법과 일치하고
  줄바꿈 포함 120자 이하일 때만 분류 근거로 인정한다. 빈 제목이나 발주기관
  라벨이 표제의 첫 줄을 값으로 가져오지 못하게 한다.
- 제목 값 전체를 감싼 인용부호 한 쌍 `「」`, `『』`, `“”`, 큰따옴표, `[]`, `［］`는
  제거하고 그 내부 공백을 한 칸으로 합친다. `[재공고] 사업명` 같은 접두어나
  값 내부 괄호는 유지한다. 문자를 추측해 고치거나 빠진 공백을 삽입하지 않는다.
- 값이 있는 제목 라인의 인용부호가 열려 있으면 다음 한 줄에서 닫히는 경우만
  이어 읽는다. 값 전체는 300자 이하이며 빈 줄·다른 라벨·절 표시는 넘지 않는다.
  세 줄 이상의 값이나 인용부호 없는 줄바꿈은 합치지 않는다. 닫히지 않은 제목은
  빈 값으로 남겨 스키마 또는 충돌 검증이 거절하게 한다.
- 계약기간은 두 ISO 날짜를 ` to ` 또는 `/`로 연결한 값만 해석한다.
  상대 기간·자유 문구는 선택 필드에서 제외한다. 명시적 날짜 형식이지만 존재하지
  않거나 순서가 뒤집힌 날짜는 제외하여 숨기지 않고 스키마에서 거절한다.

정규화되는 것은 제안된 제목 값뿐이다. 근거 인용문에는 원래 인용부호와 줄바꿈,
공백이 그대로 남아야 한다. Hosted 제안도 동일한 로컬 검증을 통과해야 한다.

## 검증과 운영 경계

새 회귀 사례는 실제 추출기·검증기를 호출하여 정상 서식, 근거 변조, 페이지 경계,
혼합 괄호, 다른 분류와의 충돌, 제목으로 잘못 소비되는 표제, 잘못된 날짜와
상대 기간으로부터 날짜를 만들어 낸 제안을 확인한다. 기존 필드 필수 조건과
개인 정보 없는 평가 진단도 함께 검증한다. DB 저장·재실행·credit 처리와
Docker·브라우저 검증은 전체 CI의 별도 실행 결과로 확인한다.

규칙과 실제 hosted system prompt가 바뀌므로 추출 identity도 달라진다. 과거 결과를
덮어쓰지 않으며, 기존 결과를 읽을 때도 현재 검증기를 통과해야 한다. 과거의
인용부호 포함 제목은 새 규칙과 맞지 않아 view에서 제외될 수 있다. 기존 reconciler는
적합한 저장 페이지가 있는 과거 버전을 새 identity로 재처리할 수 있다. Hosted 모드로
운영 중이라면 새 외부 요청과 과금 가능성이 있다. 이 변경으로 hosted 모드를 켜거나
새 유료 workflow trigger를 추가하지 않는다.

기존 Claude 실측과 OCR 실측은 당시 버전의 역사적 결과로 보존한다. 새 규칙에서
기존 Claude의 정확도·토큰·지연시간이 그대로 재현됐다고 주장하지 않는다.
공개 문서의 작은 편의 표본은 개발 진단이며 독립 일반화 성능 검증이 아니다.

기준선은 [9월 24일 후보 실행](../artifacts/evaluation/ocr-candidate.json)의

인식된 글자가 바뀐 결과가 아니라 같은 텍스트의 서식 해석 변화다. 반복 실행의 품질
지표·검증 결과·실패 상태도 모두 같았다. 정답과 분모를 변경하지 않았다.

| 그룹 또는 사례 | 제안 정답 필드 v2 → v3 | 검증 통과 정답 필드 v2 → v3 | v3 완료 |
| --- | ---: | ---: | ---: |
| 원본 스캔 2건, 각 첫 페이지 | 0/6 → **2/6** | 0/6 → **0/6** | 2/2 |
| 광주·한국인터넷진흥원 첫 페이지 렌더 | 0/4 → 0/4 | 0/4 → 0/4 | 2/2 |

| 위 그룹 중 여주 개별 사례 | 1/3 → **2/3** | 0/3 → **2/3** | 1/1 |

원본 스캔은 제목 두 개를 맞혔지만 발주기관·분류가 여전히 없어 전체 결과가 거절된다.
관리기관 표기나 업무 설명에서 필수 값을 추론하지 않았다. 여주는 새로 지원한
`용역 소액수의[견적제출] 설명서` 표제로 분류를 얻어 스키마·근거 검증을 통과한다.
발주기관과 분류 두 필드는 맞지만 제목의 닫는 괄호 뒤 공백 한 칸을 OCR이 누락해
엄격한 정답 일치에는 실패한다. **검증 통과는 원본 문서와의 정답 일치를 보장하지 않는다.**
검증기는 OCR 텍스트에 근거한 값인지 확인하며 인식 자체의 오류를 복구하지 않는다.

중앙근로자복지센터는 두 번 모두 후보 실행 실패(`ValidationError`)다. 성공한 여주만으로
그룹 정확도를 계산하지 않는다. 그룹 anchor 분모 4도 유지한다. 전체 후보는 매번
5건 완료·1건 실패이며 두 명령 모두 결과 파일을 남기고 종료 코드 1로 끝났다.
원본 스캔 anchor는 8/8, 광주·한국인터넷진흥원은 6/8로 기준선과 같다.
완료 사례 시간은 첫 실행 6.07~12.39초, 반복 5.61~11.44초였고, 두 실행의 페이지별
최대 RSS 범위는 690.95~716.19 MiB였다. 자원 조건과 완료율에 근거해 운영 채택은
계속 보류한다. 후보의 첫 페이지 실행을 전체 PDF나 512 MiB 워커 성능으로 해석하지 않는다.

### 기존 Tesseract 경로 재확인

같은 clean 소스와 기존 모델로 다음 세 평가도 다시 실행했다. 모두 종료 코드 0이며,
이는 실행 완료를 뜻한다. 구조화 품질이 충분하다는 뜻은 아니다.

원본 스캔의 전체 문서와 채점 페이지 텍스트 해시는 이전 진단과 일치한다.
렌더 대조군의 원문 텍스트 검증 통과 필드도 각각 0/4와 3/6으로 기존 결과와 같다.
세 변형은 같은 원문에서 파생된 상관된 이미지이며 독립 문서 수로 세지 않는다.
최신 artifact의 `selection`은 이미 관찰한 개발 표본임을 표시한다.
`initial_selection_note`는 원래 수집 시점의 manifest 기록이며 현재 규칙이 이 문서와
독립적으로 개발됐다는 주장이 아니다. 역사적 artifact와 frozen manifest는 보존했다.

## 재현

기존 manifest와 모델·원본 SHA-256을 그대로 사용한다. 별도 PP-OCRv5 가상환경,
1 GiB 주소 공간, 첫 페이지만 처리하는 실험 범위도 바꾸지 않는다.

```sh
RUN_ENVIRONMENT=local-korean-form-spans-v3 PYTHONPATH=apps/api \
python scripts/run_ocr_candidate_eval.py \
  --source-dir /path/to/original-pdfs --models /path/to/verified-models \
  --candidate-python /path/to/ocr-candidate/bin/python \
  --manifest data/eval/public_scan_manifest.json \
  --manifest data/eval/public_ocr_manifest.json \
  --manifest data/eval/public_ocr_forms_manifest.json \
  --output /tmp/ocr-candidate-form-spans-v3.json
```

실패한 사례가 있으면 결과를 기록하고 종료 코드 1로 끝나며 해당 그룹의 정확도는
`null`이다. 성공한 사례만 골라 그룹 전체의 정확도를 계산하지 않는다. 전체 PDF의
생산 워커 실행과 후보의 첫 페이지 실험은 분리해서 해석한다.
