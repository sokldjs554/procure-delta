## 이번 보완

1. 정규화 대기열: 한 호출의 SQL 조회와 처리량을 기본 100건, 설정 1–1000건으로 제한한다.
   미래 재시도·terminal 정규화 실패가 앞쪽을 차지해 뒤 작업이 굶지 않아야 한다.
   이미 영속화된 raw 데이터의 ingest 실패 복구는 유지한다. 재시작 후에도 다음 배치를 처리한다.
2. 추출 검증: 모델이 명시적으로 잘못되거나 모순된 예산·날짜를 생략해도 승인하지 않는다.
   기존 명시적 서식 해석 범위 안에서 검사하며, 자유형 문서 전체의 의미 이해를 주장하지 않는다.
3. 평가 증거: 실제 합계와 맞지 않는 호출·토큰 절감률을 거절한다. 과거 유효한 hosted 측정은
   보존하되 현재 extractor 계약과 일치하는지는 별도 구조화 값과 화면 안내로 표시한다.
4. 오류 추적: SDK의 지역 변수 수집을 끄고, 수신된 exception/thread/top-level 스택에서도
   지역 변수와 첨부된 원문 소스 맥락을 제거한다. 파일·줄·함수 등 진단 위치는 남긴다.
5. 메신저: 기존 웹훅의 명시적 Slack payload 형식을 추가한다. 운영자 설정으로만 선택하며
   기본은 기존 generic이다. Slack 텍스트·블록 형식과 제한, 사용자 입력의 멘션 억제,
   성공 응답, 재시도·SSRF·비밀정보 경계를 검사한다. 실제 발송은 하지 않는다.

## 경계

- 공개 데모는 합성이며, 실제 PostgreSQL/Redis/worker는 CI 통합 검증과 구분한다.
- 유료 리소스·실제 결제·메신저 발송·추가 외부 LLM 호출은 이번 변경에서 실행하지 않는다.
- 결제사·상품·구독 정책이 없는 상태에서 임의 청구 정책을 정하지 않는다. 외부 결제와
  구독 갱신은 명시적 미구현 항목으로 남기고, 이미 검증된 내부 원장과 구분한다.
- OCR 품질 미달, 실제 대규모 공개 데이터, GCP/AWS 운영 경험은 코드 추가로 달성한
  것으로 쓰지 않는다. 각 부족한 항목의 다음 검증에 필요한 입력을 대조 문서에 남긴다.
- 기존 역사적 측정 artifact는 덮어쓰지 않는다. 코드 수와 테스트 수로 일반화를 주장하지 않는다.
