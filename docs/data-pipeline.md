# 수집과 문서 처리

## 데이터 종류

1. `mock`: 포함된 합성 공고. 실제 공개 데이터가 아니다.
2. `lifecycle-demo-<run-id>`: 사용자 시연용 5단계 자료. 공고·개정본은 같은 공고의 두 버전이며 낙찰·계약은 별도 노드이다.
3. `koneps-services`: 공식 용역 입찰공고 endpoint 어댑터. 실제 키 호출은 이번에 실행하지 않았다.
4. `benchmark-<uuid>`: 명시적 로컬 부하 검증으로만 생성한다. 추천 성공률 데이터가 아니다.

## 처리 계약

수집 payload는 normalization 전에 그대로 DB에 저장한다. source/id/payload-hash 조합으로 중복 수집을 제거한다.
공식 API는 pageNo/numOfRows/totalCount/실제 records 수를 검증하고 잘린 응답이면 cursor를 넘기지 않는다.
HTTP 429/5xx/timeout은 제한된 backoff 후 재시도하고, 재시도로 회복할 수 없는 오류는 실패 이력에 남긴다.

첨부파일은 허용 호스트·HTTPS·DNS 주소·리다이렉트·바이트 크기를 검사한다. raw bytes와 체크섬을 보존한 후 파싱한다.
현재 HWP 경로는 지원하지 않는 문서로 분류하는 어댑터 경계다. HWP 내용 추출을 완성했다고 주장하지 않는다.
기본 합성 OCR 어댑터는 패키지에 고정된 특정 합성 스캔에만 알려진 텍스트를 반환한다. 이는 분기/복구 테스트이지 실제 OCR이 아니다.
별도 OCR 평가는 Tesseract에 영어 합성 이미지 3장을 한 배치로 넘겨 실제 인식 결과를 잰다.

구조화 출력은 Pydantic 계약·페이지별 인용·문자 그대로의 필드 근거·기간/금액 논리를 검사한다.
미확인 자격을 임의로 '없음'으로 바꾸지 않는다. eligibility가 실패하거나 확인 필요하면 ranking이 이를 우회하지 않는다.

## 생명주기와 알림

공식 source-scoped 식별자를 우선 연결하고, 여러 후보가 맞거나 단계가 뒤로 가면 연결하지 않는다.
Delta는 실제 필드/문서 변화와 영향 rule-code를 남긴다. 원본/추출의 문서 처리 상태가 준비되지 않았으면 현재 확정 비교로 노출하지 않는다.
관심 등록 시각보다 앞선 개정본을 '새 변경'처럼 발송하지 않는다. 로컬 시연에서도 등록 → 개정본 저장 → outbox 생성 → 실제 로컬 영수증 순서를 따른다.

`app.demo.seed`는 CLI 전용이며 새 HTTP 관리 쓰기 endpoint를 추가하지 않았다.
합성 문서는 제한된 `lifecycle-demo:<date>:<run-id>:<0..4>` 키로만 생성한다. 사용자 파일 경로나 임의 HTML을 이 경로로 읽지 않는다.
